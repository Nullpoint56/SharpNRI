## Added
- NRI v192
- `Nri.BindingVersion`, `Nri.DescsVersion`, `Nri.BindingNriVersion`, `Nri.DescsNriVersion`: the loaded packages' versions, read at run time
- `NriExternalException`: a failed third-party call (`Result.EXT_ERROR`: an upscaler SDK, NVIDIA Reflex), for falling back
- D3D12: a refused pipeline cache reports why as an INFO (another driver version, another adapter, not a pipeline library); still `OUT_OF_DATE`

## Fixed
- A failed vendor upscaler creation throws `NriExternalException` (or `NriUnsupportedException`, or `NriException` with `INVALID_ARGUMENT` or `OUT_OF_MEMORY`, when the vendor's code says so) and reports an ERROR naming the call; a failed dispatch reports one too
- D3D12 device creation with the debug layer: no `[989]` `CheckFeatureSupport` warnings
- D3D12 debug layer: no warnings `[963]`, `[964]`, `[971]` for a pipeline not yet in the cache or a cache from another driver or adapter
- An application's `ResolvingUnmanagedDll` handler for "NRI" runs whenever it was registered (SharpNRI's own handler threw and ended the chain); a missing NRI library is explained at device creation and adapter enumeration
- A `SharpNRI.Descs` package other than the one `SharpNRI` depends on fails the build (`SHARPNRI005`) and device creation (`INVALID_SDK`)
- `NriPipelineLayoutDesc.ShaderStages` documents NRI's rules
- The guide and README describe the latest release without naming a version

## Breaking changes
- Every package moves to NRI v192: 192.0.0-beta.1, `SharpNRI.Descs` included
- `SharpNRI.AgilitySDK` requires `Microsoft.Direct3D.D3D12` 1.620.2
- D3D12 `EnableGraphicsApiValidation` on an Agility SDK path without `d3d12SDKLayers.dll` throws `NriUnsupportedException` (the device ran unvalidated); set `SharpNRIAgilityDebugLayer` in a Release build that validates
