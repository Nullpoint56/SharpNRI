**NRI v191**

## Changes

### Added
- Shared resources in core: `NriDevice.CreateSharedBuffer`, `CreateSharedTexture`, `CreateSharedFence`, `CreateSharedBinaryFence`, `GetSharedHandle()` on buffers, textures and fences, `NriSharedHandle.Detach()`; `NriBufferBarrier.SrcQueue` / `DstQueue` for hand-offs to an external user.
- `NriAdapter.Enumerate(GraphicsAPI)`; a Vulkan device created without an adapter probes Vulkan only.
- `TryCreateSwapChain`; `SwapChainBits.LATEST_READY` (FIFO latest-ready with VSYNC).
- `NriDeviceOptions.EnableD3D12GpuBasedValidation`, `VkInstanceCreateInfoNext` (layer settings per instance), `VkEnumeratePhysicalDevicesAfterCreation`.
- Attachment resolve stages and accesses (`RESOLVE_ATTACHMENT`, `RESOLVE_ATTACHMENT_SOURCE` / `_DESTINATION`, `ALL_ATTACHMENT`, `ALL_RESOLVE`).
- Video: AV1 `PictureDesc`, `Av1PictureDesc`, `SavedFrameStates`, skip-mode frames; H.265 encode picture desc.

### Fixed
- An exception carries the failing call's own error text, not an earlier call's from any thread.
- `NriMemory` refuses disposal while resources are bound to it (NRI kept the allocation, and on D3D12 later devices failed).
- `NriSharedHandle` closes once; a second `Dispose` could close a handle the process had reused.
- Host-memory texture copies check the span before NRI writes past it.
- `CreateQueryPoolVK` maps acceleration-structure and micromap size queries to the right type.
- `WriteShaderGroupIdentifiers` checks the span size in 64 bits.
- A presenting Vulkan process under RivaTuner's implicit layer no longer dies at the first present.
- `NRI.dll` loads `d3d12.dll` and `dxgi.dll` only when D3D12 is used.

## Breaking changes
- The shared-handle extension (`SharedHandles`, `TrySharedHandles`) is gone; the calls are on the device and the objects. `CreateSharedTexture` takes a `TextureDesc`. `NriSharedHandle` is a class whose constructor takes the device; `SharedHandle.offset` is gone.
- `AcquireNextTexture` and `QueuePresent` return `NriSwapChainStatus` (`OutOfDate` is a status, not an error).
- `NriVertexBuffer` and `SetVertexBuffer` take the stride without a default.
- From NRI v191: `StageBits` and `AccessBits` values are renumbered (do not mix this release's assemblies with another version's `NRI.dll`); `DescriptorSetBits` and `DescriptorSetDesc.flags` are gone; `UpscalerType.METALFX_DENOISED` is `METALFX_DENOISER`.
