## Added
- Published on NuGet.org
- XML documentation in the packages
- `runtimes/<rid>/upscaler-runtimes.json` in SharpNRI.Native.Upscalers: vendor runtime versions and SHA-256
- Vendor upscaler failures (creation and dispatch) reported as errors, in release builds too
- Zero allocation measured for every per-frame call of the binding

## Fixed
- Vulkan: crash at the first present under RivaTuner Statistics Server
- D3D12: micromap creation refused by the debug layer
- Vulkan: AV1 session parameters without a colour description refused (NVIDIA still needs a host-visible AV1 bitstream)
- `CreateStreamer` with no constant buffer refused by validation
- Lavapipe on Windows: crash for pipelines without a logic op
- `WriteShaderGroupIdentifiers` past the pipeline's groups crashed the process; now `INVALID_ARGUMENT`
- Vulkan: pipeline-statistics pools without mesh-shader queries refused, with a wrong query size
- Vulkan: `ENABLE_DRAW_PARAMETERS_EMULATION` refused plain indirect draw records
- `NriAccelerationStructure.Buffer`, `NriMicromap.Buffer`: a new wrapper per read
- Annotations: native allocation per call
- Docs: `LATEST_READY` with `VSYNC` does not cap the frame rate

## Breaking changes
- `NriDeviceOptions.VkEnumeratePhysicalDevicesAfterCreation` removed
- `NriApi.HAS_BUFFER` is `static readonly`
- `NriCopyImguiDataDesc`, `NriStreamBufferDataDesc`, `NriStreamTextureDataDesc` are `readonly ref struct`
