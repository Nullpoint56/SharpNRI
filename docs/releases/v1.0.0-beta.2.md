**NRI v191**

## Changes

### Added
- Published on NuGet.org: `dotnet add package SharpNRI --prerelease`. The packages carry a readme and XML documentation (IntelliSense).
- `SharpNRI.Native.Upscalers` records the vendor runtimes it was built against (listed above) in `runtimes/<rid>/upscaler-runtimes.json`, with each file's version and SHA-256: the versions an application ships beside it.
- A failed vendor upscaler call reports why through the message callback, in release builds too: a missing or incomplete FSR loader, `ffxCreateContext`, the XeSS calls, NGX initialization and feature creation, and a failed dispatch (`ffxDispatch`, `xessD3D12Execute`, NGX evaluation), which used to leave the output unchanged without a word.
- Zero allocation covers every per-frame call of the binding, not only a representative frame: every command and overload, submission, queue, fence, query and descriptor call, the static helpers, and every extension's per-frame calls (guide: Zero allocation). A test fails for any public call added later until it is measured.

### Fixed
- Vulkan applications presenting while RivaTuner Statistics Server runs (the overlay of MSI Afterburner, CapFrameX and HWiNFO) ended at the first present with 0xC0000409. NRI now lists physical devices with `vkEnumeratePhysicalDevices`, as the layer expects, without the extra call beta.1 made after device creation.
- D3D12 micromaps: the debug layer refused every micromap creation (`[1162] ... InputBuffer and PerOmmDescs can't be null`); the size query now passes the dummy addresses the DXR specification asks for.
- Vulkan AV1 encode: session parameters from a sequence without a colour description were refused (`VK_ERROR_INVALID_VIDEO_STD_PARAMETERS_KHR`); the colours are now passed as "unspecified", as AV1 defines them.
- `CreateStreamer` with the default (zero) constant buffer size was refused by NRI validation for its constant buffer location, which is not used then.
- Lavapipe on Windows: every pipeline without a logic op crashed the driver; NRI now passes a valid value for the disabled logic op (a driver workaround, harmless everywhere).
- `WriteShaderGroupIdentifiers` with a group range past the pipeline's groups ended the process on D3D12 and Vulkan, also with NRI validation on; validation now refuses the range with `INVALID_ARGUMENT`.
- Vulkan pipeline-statistics query pools on a device with mesh shaders but without mesh-shader queries drew a validation error at creation and reported a query size two counters too large.
- `ENABLE_DRAW_PARAMETERS_EMULATION` on Vulkan: indirect draws with the plain `DrawDesc` / `DrawIndexedDesc` records were refused. The flag is D3D12 and Metal only and now has no effect on Vulkan, so it can be set on every backend.
- `NriAccelerationStructure.Buffer` and `NriMicromap.Buffer` made a new wrapper on every read (a barrier per frame allocated); the wrapper is now made once per object.
- Command-buffer, queue and thread annotations allocated native memory for their name on every call; names up to 255 UTF-8 bytes are now encoded on the stack.
- Documentation: `SwapChainBits.LATEST_READY` with `VSYNC` does not cap rendering at the refresh rate; the display shows the newest ready image at each vblank.

### Notes
- NVIDIA's Vulkan driver (617.14 and 621.14 measured) fails an AV1 encode into a bitstream buffer without `HOST_VISIBLE` memory, silently: put the AV1 bitstream in `HOST_READBACK` memory there (guide: Video).

## Breaking changes
- `NriDeviceOptions.VkEnumeratePhysicalDevicesAfterCreation` is gone: NRI enumerates physical devices itself, so the option has nothing left to do. Remove it from device options.
- `NriApi.HAS_BUFFER` is `static readonly`; it could be assigned, process-wide. Use `NriBuffer.HasBuffer`.
- `NriCopyImguiDataDesc`, `NriStreamBufferDataDesc` and `NriStreamTextureDataDesc` are `readonly ref struct`s; their properties were already init-only.

## Verified
NVIDIA GeForce RTX 4070 SUPER (Vulkan, D3D12) at 4f0f48c ([coverage](https://github.com/Nullpoint56/SharpNRI/blob/v1.0.0-beta.2/docs/coverage.md)); Mesa llvmpipe (lavapipe, Vulkan) on Linux at 4f0f48c; Microsoft Basic Render Driver (WARP, D3D12) and lavapipe on Windows and Linux by CI on the release commit, whose code is 4f0f48c's.
