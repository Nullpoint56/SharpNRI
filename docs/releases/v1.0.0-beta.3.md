## Added
- SharpNRI.AgilitySDK: copies the Agility SDK runtime at NRI's version into `AgilitySDK\`, build error on another version; debug layer in Debug builds
- With SharpNRI.AgilitySDK, a missing `AgilitySDK\D3D12Core.dll` is an error, not the inbox runtime
- Device creation refuses an NRI library or SharpNRI.Descs of another NRI version (`INVALID_SDK`, both versions named)
- `TryCreateSharedFence`, `TryCreateSharedBinaryFence`, `TryCreateSharedBuffer`, `TryCreateSharedTexture`
- `Nri.NriVersion`, `NriHeaders.Version`
- NRI's header comments as XML docs on the generated types
- Trimming and Native AOT declared (`IsAotCompatible`)
- A missing native library names the file, the RID, the directories searched and the package
- Licences copied to `licenses\<package>\<rid>\` beside the application
- Windows: `NRI.dll` needs no Visual C++ runtime (static C runtime)

## Fixed
- `dotnet publish -r` failed, or the licences overwrote each other and the application's `LICENSE.txt`
- SharpNRI.Native.Upscalers did nothing unless SharpNRI was referenced with `ExcludeAssets="native"`
- Package dependencies were minimums; SharpNRI → SharpNRI.Descs, SharpNRI.Testing → SharpNRI, SharpNRI.Native.Upscalers → SharpNRI are exact
- SharpNRI.Testing: `SHARPNRI_TEST_SOFTWARE=0` did not override GitHub Actions
- SharpNRI.Testing: probing Vulkan created D3D12 devices
- SharpNRI.Testing: a validation layer older than NRI's headers failed every Vulkan test instead of reporting it
- Package README linked master instead of the release
- Package description named macOS arm64 and "Alpha"

## Breaking changes
- SharpNRI.Descs versioned by NRI: 191.0.0-beta.1, new only when the descs change
- SharpNRI.Native.Upscalers depends on SharpNRI and replaces its native library
