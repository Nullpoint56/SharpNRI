**NRI v191**

## Changes

### Added
- C# binding over NRI: Vulkan, D3D12 and NONE. One class per NRI object, one method per command, one class per extension (ray tracing, mesh shaders, descriptor heaps, swap chain, low latency, video, streamer, upscalers, ImGui, the Vulkan and D3D12 wrappers), and shared buffers, textures and fences in core.
- Packages: `SharpNRI`; `SharpNRI.Descs`, every enum and desc with no native code; `SharpNRI.Testing`, a validated headless device per backend; `SharpNRI.Native.Upscalers`, NRI with NIS, FSR and XeSS compiled in.
- A frame (pool and allocator reset, descriptor writes, recording, submit, wait, acquire, present) allocates nothing on the managed heap.
- D3D12 on the Agility SDK from Microsoft's `Microsoft.Direct3D.D3D12` package, copied into `AgilitySDK/` beside the application (guide: Agility SDK).

### Fixed
- Vulkan devices without tessellation, geometry, task, mesh or ray tracing shaders (MoltenVK, or `DisableVkRayTracing`): barriers and fence waits on `ALL_SHADERS`, and pipeline layouts whose stages are `ALL`, no longer name those stages, which the validation layer refused.
- FSR on Vulkan: the runtime check names the files NRI v191 loads, `amd_fidelityfx_loader_vk.dll` and `amd_fidelityfx_upscaler_vk.dll`; it named FidelityFX SDK v1.1.4's `amd_fidelityfx_vk.dll` and refused FSR with the right files installed.

## Breaking changes
For code written against PrismNRI 0.4.0-alpha, this library's earlier name:
- Package ids, assemblies and namespaces are `SharpNRI`, `SharpNRI.Descs`, `SharpNRI.Testing`, `SharpNRI.Native.Upscalers`; environment variables `SHARPNRI_*`; MSBuild properties `SharpNRI*`.
- No Agility package: take `Microsoft.Direct3D.D3D12` as the guide shows.
